# 08　OneRec-V2 如何重算一次推荐的成本与奖励

[全书目录](README.md) · [上一篇](07-OneRec与工业版V1.md) · [下一篇](09-MiniOneRec代码与实验.md)

继续追踪商品 3681。预测下一款线材时，历史可能有几百个位置，答案却只有三位码。如果扩大模型的大部分算力都用来反复处理历史，还值得继续堆编码器吗？另一处问题在训练时出现。模型自己生成了 3681，奖励模型给它高分，但用户是否真的愿意看、愿意买，只有它**真正获得曝光**后才可能观察到。OneRec-V2 分别改变了历史进入模型的方式和奖励进入训练的方式。线材用于解释接口，本章报告的参数、实验和观看信号来自快手短视频。[07　OneRec 与工业版 V1](07-OneRec与工业版V1.md) · [V2 报告 §1](https://arxiv.org/html/2508.20900v4)

## 为什么当期瓶颈是处理历史

从 V1 展开一次前向，用户静态特征和行为先经过多层 encoder，每层更新每个历史位置的表示。解码器生成目标的每一层还要从历史表示准备供交叉注意力使用的 K、V。输入很长、目标仅 3 个码时，光是加大解码器里的专家数量，也无法自动把计算移出历史侧。报告表 1 对 1B 参数、512 个上下文位置做 FLOPs 估算，目标解码占 2.34%，所以 $100\%-2.34\%=97.66\%$ 在上下文处理上。这个分母含 encoder 变换和 decoder 对上下文的投影，度量的是算术量，实际时延还受访存、批量和内核实现影响。[V2 §2.1 表 1、附录 B](https://arxiv.org/html/2508.20900v4)

~~~text
V1    历史 → 多层编码更新每个历史位置 → 各 decoder 层投影各自的历史 KV ┐
                                                                       ├→ 三位目标码
                                   目标状态 → 自注意力 → 读历史 → FFN ┘

V2    历史 → Context Processor → 一次准备共享 KV ───────────┐
                          ┌────────────────────────────────┤
      BOS 与已生成的码 → 每层目标状态提问读 KV → 目标自注意力 → FFN → 下一码
~~~

“Lazy”体现为深层网络主要更新目标状态。历史仍被使用。表 1 对上下文的开销简化得较多，做工程预算更适合跟进报告表 2、表 3 的具体配置。[V2 §2、图 4](https://arxiv.org/html/2508.20900v4)

## 图 4 如何实现成一个 block

用户画像、近期和长期行为先投影到统一宽度并沿序列拼起来。设 $B$ 是请求数，$N$ 是上下文位置数，$H$ 个查询头共享 $G$ 个 K、V 头，每头宽 $d_h$。上下文最后一维是 $S_{\rm kv}L_{\rm kv}Gd_h$。$L_{\rm kv}$ 决定产生多少套 KV 供深层共享，$S_{\rm kv}$ 决定每套里的 K、V 共享表示还是分开。取最省的一种 $L_{\rm kv}=S_{\rm kv}=1$，上下文 reshape、归一化后直接作为所有层共用的 $K=V$，张量为 $[B,N,G,d_h]$。[V2 §2.2.1 式 (1)–(4)](https://arxiv.org/html/2508.20900v4)

目标侧取 `[BOS,s1,s2]`，每个位置学习预测 `[s1,s2,s3]`。用 $X\in\mathbb R^{B\times3\times d_{\rm model}}$ 记本层输入。下表按计算顺序阅读，每行均含残差连接。[V2 §2.2.2 式 (5)–(10)](https://arxiv.org/html/2508.20900v4)

| 层内操作 | 算的是什么 | 张量由谁产生 |
|---|---|---|
| ① 目标读历史 | $Q=W_Q\mathrm{RMSNorm}(X)$，每个头用 $\mathrm{softmax}(QK^\top/\sqrt{d_h})V$ 读取历史。投影后得到 $X'=X+\mathrm{CrossAttn}(\cdot)$ | Q 来自本层目标，逻辑权重为 $[B,H,3,N]$，K 与 V 复用上下文处理器的输出。 |
| ② 目标码之间通信 | $X''=X'+\mathrm{CausalSelfAttn}(\mathrm{RMSNorm}(X'))$ | 每个目标位置只能读取其前缀，逻辑权重为 $[B,H,3,3]$。 |
| ③ 非线性变换 | $X_{\rm next}=X''+\mathrm{FFN}(\mathrm{RMSNorm}(X''))$。配置允许以 MoE 实现部分前馈层 | 输入输出都为 $[B,3,d_{\rm model}]$。最终按码位做归一化和线性分类，得到 $[B,3,K_c]$，$K_c$ 为该级码本大小。 |

**手算一个注意力头。** 先把 batch、头宽与目标数各缩为 1，暂省输出投影与残差。令本次查询 $Q=1$，两条历史的共享表示 $K=V=[0,\ln 3]$。两项点积分别是 0 与 $\ln 3$，softmax 后为 $(1/4,3/4)$，此时读回的标量是 $(3/4)\ln 3\approx0.824$。同一份 KV 可供下一层读取，但新一层的 Q 由新的目标状态产生，读取分布仍可能改变。这是历史静态、目标动态在一次运算里的含义。

~~~python
# 逻辑伪代码。省略残差细节、batch 填充和 GQA 头组映射。
kv_sets = context_processor(profile, short_history, long_history)
x = target_embeddings([BOS, s1, s2])
for layer_index, block in enumerate(blocks):
    group = (layer_index * len(kv_sets)) // len(blocks)
    keys, values = kv_sets[group]
    x = x + block.cross_attention(block.norm1(x), keys, values)
    x = x + block.causal_self_attention(block.norm2(x))
    x = x + block.feed_forward(block.norm3(x))
logits = position_specific_heads(x)
loss = cross_entropy(logits, [s1, s2, s3], reduction="mean")
~~~

**还剩哪些开销。** 每层 cross-attention 仍要比较目标和历史，逻辑打分工作量随 $BHTNd_h$ 增长，$T=3$。即使共享 KV，增大历史长度或推理 beam 也会增加访问量。以 $B=1,N=8,H=4,G=2,d_h=2$ 为例，共享的一套上下文张量有 $1\times8\times2\times2=32$ 个标量，单层的逻辑打分张量则有 $1\times4\times3\times8=96$ 个标量。两者分别描述历史存储量和注意力比较规模，具体内核可以避免完整物化打分矩阵。[V2 §2.2–2.3](https://arxiv.org/html/2508.20900v4)

## 怎样区分“架构省了算力”和“共享 KV 有用”

| 控制条件 | 改动 | 作者报告的结果 |
|---|---|---|
| 同为约 1B 参数，按实验统一的三位码平均损失比较 | 表 2 里的 1:1 Encoder–Decoder → Lazy Decoder | 296.36 → 18.89 GFLOPs，收敛损失 3.28 → 3.27。这个对照同时改变多项结构。 |
| 同一个 1B、18 层 Lazy，固定 K/V 共享表示，只减跨层 KV 套数 | 表 3 里的 18 套 → 1 套 | 23.95 → 18.89 GFLOPs，batch 512 下激活元素数 2.83B → 1.24B，表中两项收敛损失均为 3.27。这个对照更直接回答能否跨层共享。 |

两行按 V2 的平均生成损失做比较。六月 V1 报告基线的原始损失取三码之和，跨报告直接把两个 loss 相减容易读错。V2 的 8B 结果属于扩模实验，线上主实验用 1B、上下文长 3000、beam 512。线上报告的 L20 时延为 36 ms，这个配置才是解读该数字的前提。[V2 §2.3 表 2–5、§4](https://arxiv.org/html/2508.20900v4)

## 从视频播放反馈生成优势

在快手场景，完整 5 秒的视频与完整 60 秒的视频都有“完播”，播放时长却差很多。V2 对每个用户把历史视频按**视频自身时长**分桶，在相近时长的桶里比较**实际播放时长**。令 $\mathcal H_{u,b}$ 为用户 $u$ 在时长桶 $b$ 里已有视频的播放时长，$w_i$ 为本次播放时长，其经验分位为

$$
q_i=\frac{\#\{w\in\mathcal H_{u,b}:w\le w_i\}}{\#\mathcal H_{u,b}}.
$$

一个 60 秒的目标视频播放了 45 秒。同一用户同桶历史播放时长为 10、20、30、50 秒，于是 $q_i=3/4$。假如本批取前四分之一时的阈值为 0.70，且用户无明确负反馈，这条样本给 $A_i=+1$。阈值为 0.80 时会过滤。若用户明确标记不喜欢，则为 $A_i=-1$。这一步用批内筛选和真实行为替代了必须先对每个新物品调用 RM 的依赖。[V2 §3.1.1、图 8](https://arxiv.org/html/2508.20900v4)

回到线材。Amazon 的这条记录只有真实交互顺序，给了下一件物品，缺少视频总长、观看秒数、同用户的分桶播放历史和显式负反馈。用它可以算 3681 在预测列表中的名次，却不能据此构造上述快手时长优势。若另有电商曝光、加购和购买日志，应重新定义电商反馈及归因窗口，并在商品价格、品类和库存等条件下验证它与业务目标的关系。[测试记录](../mini-lab/evidence/test-first16.csv) · [V2 §3.1](https://arxiv.org/html/2508.20900v4)

## GBPO 怎样控制一条负例的更新

令 $p=\pi_\theta(o|u)$ 是当前策略赋予完整物品的概率，$p_0$ 是采样策略的相应概率，$\operatorname{sg}$ 是停止梯度。V1 的 ECPO 对负例的大概率比提前限幅，V2 的 GBPO（Gradient-Bounded Policy Optimization）按优势的符号改变比值的分母。单条损失可写成

$$
L_i=-A_i\frac{p}{d_i},\quad
d_i=
\begin{cases}
\max(p_0,\operatorname{sg}(p)), & A_i\ge 0,\\
\max(p_0,1-\operatorname{sg}(p)), & A_i<0 .
\end{cases}
$$

沿用上一章的负例 $A_i=-1,p=0.30,p_0=0.10$，分母为 $\max(0.10,0.70)=0.70$，损失为 $+0.30/0.70\approx0.429$。若对照不设界的 $-A_ip/p_0$，损失为 3。这是对给定输入的前向手算，不能只拿标量损失大小判断算法好坏。看梯度时，分母里的当前概率已停止反传。对当前 log 概率的导数分别为约 0.429 与 3。对两个式子都做梯度下降，均会压低这个负例，力度不同。[V2 §3.1.2 式 (11)–(12)、图 9–10](https://arxiv.org/html/2508.20900v4)

## 读 A/B 时，把三种证据分开

- **训练信号的对照。** 表 7 在 V2 上分别用 RM 奖励、真实用户行为，以及两种独立来源的样本混合训练。作者观察到多目标 RM 更偏向互动提升，主要基于播放时长的用户反馈更偏向 App Stay Time。§4 线上主配置为了简化系统只使用反馈方案。[V2 §3.2 表 7、§4](https://arxiv.org/html/2508.20900v4)
- **整个系统的对照。** 主方案与 V1 比较，主端与极速版 App Stay Time 分别 +0.467%、+0.741%。5% 实验流量内 V2 用在部分降级请求上。架构、训练方法和反馈一起变化，因此这个差值不宜全部归给 GBPO 或 KV 共享。[V2 §4 表 8、附录 D](https://arxiv.org/html/2508.20900v4)
- **扩大接管范围的代价。** 另设的 1% 关闭缓存、组内全量请求 V2 的实验里，冷启动视频播放量相对 V1 分别下降约 44.7%、36.7%。回到线材业务，如果总体命中升高而新品候选覆盖下降，应单列新品定义和分母，再试新品专路或排序约束，比较它挤掉了多少原有有效候选。[V2 附录 D 表 9](https://arxiv.org/html/2508.20900v4)

## 练习与参考解答

1. **定位工程收益。** 每层 Attention 里还能看见形状 $[B,H,3,N]$。为什么 V2 仍可能更省？**答**　它减少了历史 token 在深层的重复变换和重复 K/V 投影。$3N$ 的目标对历史注意力还存在。测量时一起记录历史长度、batch、beam、激活量和 P95，才能解释节省的是哪部分。
2. **改一个输入并预测。** 同一个目标视频仍得到 0.75 分位，批内阈值仍为 0.70，但这次用户明确点了“不喜欢”。优势和单条损失怎样改变？**答**　优势由 +1 变 −1。若 $p,p_0$ 仍为 0.30、0.10，正例损失 $-0.30/0.30=-1$，负例损失约 +0.429，更新方向翻转。
3. **选择下一个实验。** MiniOneRec 的线材末码位列 19/21。能否直接据此决定借用 GBPO？**答**　这个观察定位到了商品区分阶段，尚未区分监督样本稀疏、SID 表征和策略训练等原因。先固定测试样本、目录和 beam，对比可比的 SFT、RL 权重或查看同前缀商品混淆。用真实的输入、候选与排名完成第 09 章实操，再决定改哪一步。[09　MiniOneRec 代码与实验](09-MiniOneRec代码与实验.md) · [实验记录](../mini-lab/README.md)
