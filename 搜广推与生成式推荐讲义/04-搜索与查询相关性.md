# 第四篇　用户明确搜索“橙色 ABS”，系统怎样找对商品

[全书目录](README.md) · [上一篇](03-粗排精排与重排.md) · [下一篇](05-广告预估竞价与预算.md)

在首页推荐里，银色 PLA 和橙色 ABS 都很像用户之前看过的打印耗材。换到搜索页，用户亲手输入 `orange ABS 1.75 mm filament`。现在材质、颜色、直径都有了直接证据。我们可以问一个可验证的问题：**同一卷在推荐召回中找不到的线材，只给搜索系统这几个词，它能从同一份目录里捞回来吗？**

我们在项目的 3,686 件商品上实际跑了标题 BM25。结果是橙色 ABS 商品 3681 排第 **2**，银色 PLA 商品 2909 排第 **188**。这是对人工构造查询的本机检索结果。原评论序列只记录了后来交互的商品，用户当时是否搜索过这个词没有记录。[本地商品目录](../mini-lab/Amazon/info/Industrial_and_Scientific_5_2016-10-2018-11.txt)

## 看一条查询怎样穿过索引

先把 `1.75 mm` 和 `1.75MM` 统一成 `1.75mm`。对查询和标题使用同一套规则，才能在索引中相遇。为每个词存一张倒排表，表里是“包含这个词的商品、它出现了几次”，还可以存位置和字段。拿到 `abs`、`orange` 的表，扫描相关条目就知道哪些商品可能匹配，线上无需逐字检查整个目录。

严格求所有词的交集会漏掉标题省略颜色、但结构化属性完整的商品。放宽为任一词命中，又会放进几乎所有写了 filament 的商品。常用分工是用较宽的词项匹配找候选，用相关性打分排优先级；对必须匹配的规格，如明确的直径，在有可靠属性时另作过滤。属性缺失代表信息未知，是否保留要按场景单独定。

对每个查询词 $t$，BM25 综合以下三个量。词在目录越少见，命中它越有辨识力；同一标题里多次出现同一词，收益逐渐饱和；长标题本来就更容易命中词，长度归一化用来校正这个优势。这里用常见的单字段形式，$N$ 为商品数，$df_t$ 为含词 $t$ 的商品数，$f$ 为当前标题词频，$L$ 为当前标题长度。[Lucene BM25 的参数和 IDF 定义](https://lucene.apache.org/core/9_12_1/core/org/apache/lucene/search/similarities/BM25Similarity.html)

$$
\mathrm{score}(q,d)=\sum_{t\in q}\log\!\left(1+\frac{N-df_t+0.5}{df_t+0.5}\right)
\frac{f(k_1+1)}{f+k_1(1-b+bL/\overline L)}.
$$

**手算一个词。** 令标题长度等于平均长度，$k_1=1.2$。同一个词出现一次时，后面的因子是 $2.2/2.2=1$；出现两次时是 $4.4/3.2=1.375$。复制一遍标题用词只有递减的收益。把 $b$ 调为 0，所有标题的长度校正都消失。再把两条同样含一次 ABS 的标题做对照，就能看到“长短”这个变量被关掉了。

## 在本机复现第 2 和第 188 名

从项目根目录执行。为了方便单步阅读，小实验枚举小目录来计算同一公式。实际大索引一般走倒排表累积分数。此实现按商品编号打破同分，不依赖外部包。

```powershell
@'
import math, re
from collections import Counter
from pathlib import Path

def tokens(text):
    text = re.sub(r"\b(\d+(?:\.\d+)?)\s*mm\b", r"\1mm", text.lower())
    return re.findall(r"\d+(?:\.\d+)?mm|[a-z]+|\d+", text)

catalog = {}
path = next(Path("mini-lab/Amazon/info").glob("Industrial*.txt"))
for line in path.read_text(encoding="utf8").splitlines():
    _, title, item_id = line.split("\t", 2)
    catalog[int(item_id)] = tokens(title)

query = tokens("orange ABS 1.75 mm filament")
n = len(catalog)
avg = sum(map(len, catalog.values())) / n
idf = {t: math.log(1 + (n - sum(t in v for v in catalog.values()) + .5) /
                   (sum(t in v for v in catalog.values()) + .5)) for t in query}

def score(words):
    tf = Counter(words)
    norm = 1.2 * (.25 + .75 * len(words) / avg)
    return sum(idf[t] * tf[t] * 2.2 / (tf[t] + norm) for t in query)

ranked = sorted(catalog, key=lambda i: (-score(catalog[i]), i))
for i in (3681, 2909):
    print(i, ranked.index(i)+1, round(score(catalog[i]), 3))
print("top5", ranked[:5])
'@ | python -X utf8 -
```

本机输出如下。第一名 2582 是另一品牌 HATCHBOX 的橙色 1.75 mm ABS 线材，它也符合查询中明确提出的四个条件。**真实下一商品排第二，完全可能仍然是正确的搜索排序。** 如果产品目标是文字相关性，应当判断各结果对这个查询的匹配程度；如果目标是“只找回那一个 SKU”，则还需要品牌、型号等额外证据。

```text
3681 2 13.365
2909 188 5.052
top5 [2582, 3681, 3648, 2707, 1132]
```

## 双塔、融合、交叉编码各增加了什么

若查询换成“给打印机用的橙色耗材”，英文标题与中文输入几乎没有共同词。语义召回可以训练两个编码器，各自把查询和商品投影到同一向量空间。商品向量离线建索引；在线一次算查询向量，检索邻居。训练希望正例的内积高过负例。一个合适的困难负例是“同颜色同直径的 PLA”，它能逼模型学习材料差异。若用户没看到某候选，就不能仅凭没有点击断言它不相关。

需要兼顾型号精确匹配和自然语言表述时，可以并行取两个短列表。BM25 分数和向量内积的尺度不同。一种朴素融合叫 RRF，只使用名次。教学取常数 $k=10$，某项在两路排第 2、第 3，融合分为 $1/12+1/13\approx0.1603$。另一项只在一路排第一，得 $1/11\approx0.0909$。前者靠两路共同支持排在前面。代价也在这里：一个冷门精确型号可能仅被倒排路找到；融合截断过早就会丢掉它。保留各路独有命中数，才能核对此问题。[RRF 的求和与截断规则](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

双塔把整条查询和整条标题各压成一个向量。精排可以把 `[查询；候选标题]` 放进同一个交叉编码器，让“ABS”与这个候选的“PLA”在词级直接交互。此时每个查询–商品对都须重新计算，通常只在较短的候选集运行。若候选中根本没有合格直径，继续换交叉编码器不会找回它。相反，若候选已有精确型号，被相似配件压下去，应检查训练对中是否区分了主体与配件。[Amazon 搜索排序基线与数据](https://github.com/amazon-science/esci-data)

## 用什么评估搜索

ESCI 为查询与候选提供 Exact、Substitute、Complement、Irrelevant 四种判断。这让“搜主件却把配套喷头排第一”有了明确的诊断对象。对官方标注候选，固定每个查询的集合，只改排序器，按官方评测配置计算 NDCG。对全库召回，可统计被标注为相关的商品有多少进入候选；目录中未被人工判断的商品保留未判定状态。分开报告规格/型号查询和宽泛需求查询，有时两组的收益方向不同。[Amazon ESCI 任务与评测入口](https://github.com/amazon-science/esci-data#task-1---query-product-ranking)

**练习一**　某请求“橙色 ABS 线材”，倒排前 50 只有正确 SKU，向量路前 50 只有同色 PLA。两路融合后 PLA 反而更靠前。换一个更大的精排一定有用吗？

**参考答案**　先看融合截断后 SKU 还在不在。已经被截掉时，先查融合预算、型号专路或精确属性条件。如果还在精排输入里，再检查精排是否识别材料词以及训练中有没有这种难负例。改变一个组件时固定其余输入，才知道是哪里起了作用。

**练习二**　复跑上面的程序，把查询改成 `orange filament`。先预测“银色 PLA 的分数会不会上升”，再预测“它的名次会不会上升”。**参考答案**　在这个单字段正权重实现里，删除查询词只会令每件商品的分数降低或持平。名次由相对分数决定，可能上升也可能下降，要重排全目录才能知道。两种预测关注的是不同的量。
