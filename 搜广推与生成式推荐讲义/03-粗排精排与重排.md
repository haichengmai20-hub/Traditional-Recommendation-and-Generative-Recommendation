假设首页最终展示 10 件商品。两条真实的 Amazon Industrial 测试请求都没能在 ItemCF 前 10 中找到目标。第 1 条的目标是橙色 1.75 mm ABS 线材（3681），它连前 50 都没进。第 12 条的目标是黑色自熔胶带（450），它排在第 13。这一区别决定了下游排序器的能力边界。**固定这 50 件候选后，排序能把胶带往前移，无法把缺席的线材排进页面。** [测试样本与候选名次](../traditional-lab/industrial-results.json)

真实大系统会在多个阶段逐步缩小候选。下面前三行用教学规模说明各阶段计算边界。最后一行是本项目实际跑的实验，可在文末复现。

```text
可以承受的大批量计算     粗排：数千候选 → 小模型或低成本特征 → 留下几百件
能够负担的复杂交互       精排：几百候选 × 用户上下文 → 每个候选的行为分数与排序
页面约束和物品之间的关系 重排：已排序候选 + 已选商品 → 一页有顺序的结果
本地实测                 ItemCF 交出 50 件 → 固定这 50 件，用另一分数重排 → 看前 10
```

最后一行的“重排”是对已有候选重新打分这个一般动作。在下文的工业分工中，我们用“精排”指逐候选算效用，用“列表重排”指显式考虑一页中物品之间的关系。工业规模、教师蒸馏、DIN、ESMM 和列表多样性在本章作机制教学。文末实验使用标题分数。

## 第一刀该怎么切：让粗排保住精排真正想看的东西

把全部召回候选送入精排，要对每个候选读取特征、与历史行为交互、执行推理。即使一次只多算 1 毫秒，对大量请求也有资源代价。粗排为每件候选计算便宜的分数，取前 M 件，再让复杂模型打分。典型的低成本输入包括召回路名次、短历史相似度和预先计算的商品特征。把候选相关的长历史注意力放在后一级，是在用一次提前淘汰换取计算预算。[COLD 工业粗排系统](https://arxiv.org/abs/2007.16122)

风险恰好出在这次淘汰。假设粗排偏好热门胶带，精排却综合规格、用户需求和购买概率。两个模型各自的离线分数可能都不错，但粗排已经把精排最看好的长尾商品扔了。**同一请求、同批候选、先不截断，在抽样流量上离线运行精排教师**，就能看到两级是否一致。在这个方案中，教师分数用于训练和离线审计。上线时由轻模型提前截断，然后由精排给留下的候选打分。[粗精排一致性研究](https://arxiv.org/abs/2205.01289)

**手算。** 同一批有 A、B、C、D、E 五件商品，教师认为最好的两件是 D 和 B。粗排只保留三件。

| 轻模型保留的三件 | 教师 Top-2 保留率 | 下游还能做什么 |
|---|---:|---|
| A、B、C | 1/2 | 可以选 B，已经看不到 D |
| D、B、E | 2/2 | 可以在 D、B 间做更细判断 |

想让第二种情形多一些，可以让学生拟合教师的相对顺序。例如教师偏好 D 胜过 A，就约束学生令 `s(D)>s(A)`。也可让学生的候选分布接近带温度的教师分布。教师自身的错误也会传下去。因此验收同时看三项：输出名额固定时的教师 Top-K 保留率，真实行为标签的保留率，以及给相同流量服务时的延迟。训练时若只看旧系统已经曝光的商品，教师见不到早早被丢掉的候选。可对抽样请求保存较宽候选，用同一个教师补打分。真实行为监督仍受曝光策略影响。

### 从一条曝光训练出粗排，再用它切一千个候选

沿用第 01 篇的视频请求 V17。用户看到视频封面，点击后才播放，播放满 10 秒算长观看。视频 337 有效曝光、被点击、播放 35 秒。这给了粗排一个点击正例，也给后面的精排一个点击后长观看正例。曝光后等观察窗结束仍未点击，才能写点击负例。如果页面会自动播放，用户可能没点就看满 10 秒，后文的条件标签要重新定义。以下尺寸来自 v3.1 教学配置。文末胶带实验用的是另一种数据，只有下一商品标签。[第 01 篇的请求与训练样本](01-请求与训练样本.md)

读张量先分清四根轴。**B** 是线上一起处理的请求数（这里为 1），**K** 是每个请求在当前阶段的候选数（粗排 1,000，精排 200）。**L** 是每条历史补齐到的长度（20），**M** 是训练批里的曝光样本数（256）。训练取 256 条曝光，每条只给一个当时展示的候选，即 K=1。线上则是同一条历史对许多候选打分。

| | 离线训练粗排 | 线上粗排同一个请求 |
|---|---|---|
| 输入从哪里来 | 固定已训练好的召回两塔版本 R1，用曝光时可用的历史与物品字段得到用户、物品两路 `[M,64]`。粗排自己的设备表和小时表各查 8 维，拼成 `[M,16]` | 从 R1 得到一个用户向量，按召回的 1,000 个 ID 到 R1 物品向量库取 `[B,1000,64]`。沿候选轴复用用户向量和粗排上下文 |
| 模型怎么算 | 拼成 `[256,144]`，同一套 MLP `144→64→1` 给每条曝光一个 logit。把原始 logits 与成熟点击标签送入 BCEWithLogitsLoss；它内部计算 sigmoid 对应的交叉熵 | 拼成 `[1,1000,144]`，逐候选应用同一 MLP，压掉最后的单值轴，得到 `[1,1000]`，sigmoid 后得到候选的预测点击率 |
| 这一步留下什么 | 反向传播只更新粗排 MLP、粗排设备表和小时表，得到 P1。R1 的两塔和 ANN 索引保持冻结。换 R2 后应核对索引及向量库的新旧版本，并重测 P1 对新向量的适配性 | 每个请求沿候选轴取前 200，高分所对应的真实 ID 才交给精排。本配置的监督来自点击，上一节的教师保留率仍可单独用来检查被它错删的候选 |

**Top-K 的索引是哪一种 ID？** 假设候选数组是 `[101,205,337]`，同序点击分是 `[0.19,0.80,0.65]`。取前二返回分数 `[0.80,0.65]` 和数组位置 `[1,2]`。取这两个位置才得到视频 `[205,337]`。精排取前 50 时也这样做，分任务概率、作者和类目必须跟着同一组位置走。若张量按宽度补位，先屏蔽无效分，并保留输出有效位，避免候选不足时把补位项当真。[PyTorch gather](https://docs.pytorch.org/docs/stable/generated/torch.gather.html)

```python
# ids、scores、creator_ids 均为 [B,K]，此处各行有效候选数均不少于 k_out
chosen_scores, pos = scores.topk(k_out, dim=1)
chosen_ids = ids.gather(1, pos)
chosen_creators = creator_ids.gather(1, pos)
# 若还携带向量 features [B,K,D]，沿同一候选轴取整行特征
chosen_features = features.gather(1, pos[..., None].expand(-1, -1, features.size(-1)))
```

## 精排逐件问：这个用户此刻看到这件商品，会怎样反应

训练样本通常是一条 `(请求、候选、当时可见的特征、实际行为标签)`。要估 pCTR，需要曝光事件作为分母、后续点击作为标签。当前 Industrial 数据只有评论交互序列，可以学“下一商品与历史的匹配程度”，也可构造对照商品训练排序。不能由这种离线分数直接读出一次曝光后的点击概率。下面用教学特征演示不同模型会改变哪一次计算。[DIN 的曝光点击任务](https://arxiv.org/abs/1706.06978) · [本地数据及口径](../traditional-lab/industrial-results.json)

### LR、FM、DeepFM：从独立加分到学习特征组合

先给逻辑回归 LR 两个二值特征，`x₁` 表示用户近期有维修行为，`x₂` 表示候选是自熔胶带。用教学参数 `z=−2+0.6x₁+0.4x₂`，再用 `σ(z)=1/(1+e^(−z))` 转为概率。两项都为 1 时，`z=−1`，输出约 **0.269**。在这条公式里，“是自熔胶带”永远加 0.4 对数几率，用户的维修兴趣不会改变这次加分。可以手造一个 `x₁x₂` 特征，可是用户、类目、价格带等字段的组合会迅速变多。

FM 给每个稀疏特征一个小向量 v，用 `Σ(i<j)〈vᵢ,vⱼ〉xᵢxⱼ` 计算两两交互。假设两个特征向量为 `(1,0)` 与 `(0.8,0.2)`，二者都出现时多加 **0.8**，得到 `z=−0.2`，概率 **0.450**。只出现其中一个，则无此交互项。同一个特征向量还会和其他特征配合学习，这比为全部稀疏组合分别拟合一个独立系数更容易共享数据。

DeepFM 把同一组特征 embedding 同时送进 FM 支路和多层感知机。前者显式给出二阶交互，后者学习更复杂组合，两路输出合并。代价是模型和服务计算更重，也更容易利用数据里的偶然相关。检验这次升级时要固定候选集、标签和时间切分：在曝光数据上比较 LogLoss、AUC 和不同流量段的校准。在只有下一项的数据上比较按请求聚合的排名指标。概率已整体高估一倍时，排序次序仍可能完全相同。[DeepFM 原文](https://arxiv.org/abs/1703.04247)

### DIN：让同一串历史为不同候选给出不同证据

第 12 条历史里既有透明胶带，也有镊子和切削液。如果先把历史平均成一个“用户向量”，那么给黑色胶带与给切削液打分时，模型收到的历史摘要相同。DIN 把**候选**也作为输入，用目标相关的局部激活单元给每条历史赋权，再把加权后的兴趣表示送入点击模型。这样用户历史相同，候选换掉以后，历史里起主要作用的行为也能换掉。[DIN 原论文](https://arxiv.org/abs/1706.06978)

取两条历史的教学向量 `e(胶带)=(1,0)`、`e(切削液)=(0,1)`。候选为黑色胶带时，假设网络给两个历史权重 0.8、0.2，得到兴趣表示 `(0.8,0.2)`。候选变成切削液时，权重变成 0.1、0.9，得到 `(0.1,0.9)`。示例为了方便心算让权重合计为 1，DIN 原文的局部激活允许权重不归一化，以保留兴趣强度。它新增的是“候选与逐条历史的交互”，服务成本随候选数和历史长度增加。固定长度、截断或缓存可省计算，也可能损失长期兴趣。

#### 候选 337 如何通过同一个 DIN-style 模块训练和服务

接刚才的视频请求。精排用自己的表 `E_item_rank` 同时查候选向量 q 与历史向量 h，二者共用精排的参数空间。这里的 q 通过候选 ID 查询得到；粗排用过的 R1 物品塔向量属于另一个模型。设 d=64，分别沿 K、L 广播，令每一个候选都与每一条历史配成一对。对一对 `(q,h)`，拼接 `[q,h,q−h,q⊙h]`，即两种表示本身、逐维差以及逐维乘积，共 4d=256 维。每个候选与每段历史使用相同的激活网络。

| 一次前向计算 | 在线，1 个请求的 200 个候选 | 训练，256 条曝光各 1 个候选 |
|---|---|---|
| 查历史、候选 embedding | h `[1,20,64]`，q `[1,200,64]` | h `[256,20,64]`，q `[256,1,64]` |
| q 新增历史轴，h 新增候选轴，广播后拼四块 | `[1,200,20,256]` | `[256,1,20,256]` |
| 激活网络 `256→1`，挤掉最后一维，用 sigmoid 给权重 | `[1,200,20]` | `[256,1,20]` |
| 乘有效历史 mask，再用各权重乘对应 h，沿 L 求和 | 每件候选一份兴趣 `[1,200,64]` | 每条曝光一份兴趣 `[256,1,64]` |
| 兴趣与候选各 64 维、用户 32 维、上下文 16 维、类目 8 维、请求时点可见的数值特征 4 维 | 拼为 `[1,200,188]`，共享 DNN `188→128`，两个 `128→1` 头各输出 logits `[1,200]` | 兴趣和候选都在 DIN **结束后**用 `squeeze(dim=1)` 去掉 K=1，拼为 `[256,188]`，相同 DNN 与头各输出 logits `[256]` |

因此一般交互张量是 `[批量,K,L,4d]`，沿 L 求和后才变成 `[批量,K,d]`。历史 mask 的原形状是 `[批量,L]`，补一条候选轴成为 `[批量,1,L]`，每个候选都屏蔽同样的填充位置。若用户只有三次行为，只让这三项参与加权和。空历史的兴趣向量为全零，用户和上下文仍能用于打分。这里用未归一化的 sigmoid 门控加权求和，这是 v3.1 选用的 DIN 风格实现。

上述 4 个数值输入依次取视频时长、发布至请求的时长、请求前 7 日可见的有效曝光数和相同窗口的平滑 CTR。V17 播放的 35 秒发生于请求之后，只用于构造长观看标签。把它拼进 188 维会让模型在训练时提前拿到答案。

### ESMM：哪些行为要在同一个分母上学

同一卷胶带有时容易引起点击，购买却很少。只用一个点击分数排序，会把点击偏好带到购买目标上。若业务定义为**先曝光、再点击、随后在窗口内转化**，可以把“从曝光一路走到转化”的概率分解：

```text
P(点击且购买 | 曝光特征) = P(点击 | 曝光特征) × P(购买 | 点击, 曝光特征)
       pCTCVR                     pCTR                    pCVR
```

若 1,000 次曝光有 100 次点击、其中 5 次购买，经验 CTR 为 10%，点击后 CVR 为 5%，每次曝光点且买的比例是 0.5%。若另一个商品的 pCTR 为 5%、点击后 pCVR 为 20%，则其 pCTCVR 为 1%。按点击排第一个更高，按点且买排第二个更高。最终使用哪一项取决于这次展示的业务目标。

传统的点击后 CVR 模型仅在已点击的子集上训练，服务时却要评估所有候选。转化样本还很稀疏。ESMM 设计两个分支，预测 pCTR 与 pCVR，并取乘积作为 pCTCVR。在所有曝光上用两个交叉熵监督 `点击` 和 `点击且转化`，共享部分表征。购买分支通过乘积获得梯度。实际检查时，先等转化观察窗成熟，再看两项输出是否校准。若允许未点击后的浏览归因转化，需单独定义这种业务路径和标签。当前评论数据缺曝光与点击，不具备复现实验所需的分母。[ESMM 原论文](https://arxiv.org/abs/1804.07931)

#### 同样把两个概率相乘，长观看头在哪些样本上学？

点击后播放使“长观看”包含在“点击”事件内，因此曝光后的长观看概率等于 `pCTR × P(长观看 | 点击,x)`，由概率链式法则得到。v3.1 用**条件 BCE**训练长观看头，和上面 ESMM 在全曝光上监督联合事件的训练方式有一处关键差别。

| 已成熟的三条有效曝光 | CTR 头用什么标签 | 条件长观看头用什么标签 | 若改用 ESMM 式联合事件监督，乘积用什么标签 |
|---|---:|---|---:|
| 视频 337，点击且看了 35 秒 | 1 | 1 | 1 |
| 另一视频，点击只看了 3 秒 | 1 | 0 | 0 |
| 第三条视频，曝光后没点 | 0 | 跳过 | 0 |

例如长观看头在这三行给出条件概率 `[0.8,0.3,0.9]`，条件 BCE 为 `(−ln 0.8 −ln 0.7)/2 ≈ 0.290`；第三行的 0.9 完全不进入本项损失。实际可对点击行选择 `long_logits` 与对应标签后算 BCEWithLogitsLoss。等价的写法是先为未点击行填占位标签 0，逐行算 BCEWithLogits，再乘 `y_click` 并除以 `max(1,点击数)`。若本批没有点击，此项数据损失与长观看头的任务梯度为零，CTR 仍按所有有效曝光训练。[PyTorch BCEWithLogitsLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.BCEWithLogitsLoss.html)

训练用 `L_rank = L_CTR + λ_train × L_long`。反向传播更新精排自己的 embedding（用户、物品、类目、设备、小时）、激活网络、共享 DNN 与任务头。每个头只接收其任务损失沿该支路传来的梯度，共享层汇集两项，R1 两塔和粗排 P1 各由自己的训练流程更新。

上线时两个头经过 sigmoid 得 `pCTR`、`q=P(长观看 | 点击,x)`。在这套业务设定中，每次点击带来 0.4 单位效用，若还长观看再加 0.6，因此每次曝光的期望效用为 `0.4×pCTR + 0.6×pCTR×q`，按它取前 50。假设 A 的两个概率是 `0.50, 0.10`，B 为 `0.40, 0.90`，A 的效用为 0.230，B 为 0.376。粗排只看 CTR 可能较早丢掉 B，这给了教师保留率一个具体检查对象。**调 0.4/0.6 可以在权重固定时改变排序；调 λ_train 改变下一次训练的梯度分配。** 本例的 Top-K 发生在推理阶段，两项训练损失都没有经过它反向传播。

## 列表重排与线上服务：用户看到的是一页

逐件打分时，两个高度相似的胶带都可能得高分。列表已有一卷黑胶带后，再加一卷几乎相同的，可能比加一个互补商品的新增价值小。MMR 按位置贪心选取，兼顾单品相关性及与已选商品的最大相似度。下式中的两项要在可比较的尺度上，λ 控制折中。[MMR 原论文](https://www.cs.cmu.edu/afs/cs/Web/People/jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf)

```text
下一件的得分 = λ × 单品相关性 − (1−λ) × 与已选结果的最大相似度
```

第一页已选一卷胶带，另一卷相似款的相关性为 0.90、相似度为 0.95。维修附件的相关性为 0.80、相似度为 0.10。设 λ=0.7，两件得分分别为 `0.63−0.285=0.345` 和 `0.56−0.03=0.53`，附件会上移。若用户明确想比较不同长度的同款胶带，过强的去重反会损害需求。应把同款重复率、品牌或品类覆盖与相关性指标一起观察。缺货等资格条件用硬过滤单独处理。

视频教学系统里，精排保留 50 个 ID 及对齐的效用分，另外按 ID 取得作者、类目、资格位和相似度向量。由 50 个向量可得 `[1,50,50]` 的两两相似度。第一次选择时已选列表为空，相似惩罚取零。每添一条，更新与已选物品的最大相似度及作者、类目计数。这里用的是带约束的贪心策略，没有独立的训练损失或反向传播；规则与惩罚系数可通过离线列表指标及受控线上实验调整，学习型列表重排另需模型、标签与损失。若每类最多两条而只剩三个合格类别，即使有 50 个候选也至多返回六条。返回较短列表时以有效位标出真实位置，或补召回后重新检查约束。最终计入 CTR 训练的仍是客户端实际曝光、标签已成熟的那些位置。

沿一次请求上服务，先取在线特征与候选 ID，再粗排截断、精排批量打分、列表重排，最后发出推荐结果并由展示端记录真实曝光。每层日志至少关联 request_id、模型或索引版本、入选商品、名次和耗时。若胶带昨天还在第 8，今天突然消失，先核对它进没进召回、是否读到当时的库存，再看是否换了特征版本或超时退回热门。只拿最终 pCTR 日志无法追回在上游丢掉的商品。[在线流程](https://datawhalechina.github.io/fun-rec/chapter_10_projects/4.online_pipeline.html) · [按请求时间拼接特征](https://docs.feast.dev/v0.50-branch/getting-started/concepts/point-in-time-joins)

## 动手：锁死 50 个候选，只换一个打分函数

选用 ItemCF 的前 50 件，版本 A 保留原顺序。版本 B 读取最近 3 件历史商品的标题，累加其 TF-IDF 单位向量作为用户表示，用内积给**同样的 50 件商品**重新打分。分数相同保留原顺序。这个便宜的打分器允许我们把“召回变了”和“排序变了”分开。先预测两件事：第 1 条可能被救回来吗？第 12 条历史里有同品牌透明胶带，黑色胶带有没有机会升到前 10？

在项目根目录（其下可见 `mini-lab`、`traditional-lab`）运行以下 PowerShell，无额外依赖。

```powershell
@'
from collections import Counter
from itertools import islice
from pathlib import Path
import math, sys
sys.path.insert(0, "traditional-lab")
import itemcf as cf
import cold_title_recall as text

root = Path("mini-lab/Amazon")
info = root / "info" / (cf.DATASET + ".txt")
catalog = cf.read_catalog(info)
neighbors, popular, counts, _, _ = cf.fit(root / "train" / (cf.DATASET + ".csv"), catalog)
vectors, _ = text.index_titles(info)
stat = Counter()
for row, (_, history, target) in enumerate(cf.rows(root / "test" / (cf.DATASET + ".csv"), catalog), 1):
    before = list(islice(cf.rank_itemcf(history, neighbors, popular, counts), 50))
    profile = Counter()
    for item in history[-3:]:
        profile.update(vectors[item])
    def score(item):
        return sum(w * profile[word] for word, w in vectors[item].items())
    after = sorted(before, key=score, reverse=True)
    assert set(before) == set(after)
    if target in before:
        stat["in50"] += 1
    ranks = [order.index(target) + 1 if target in order else None for order in (before, after)]
    if row in (1, 12):
        print("case", row, target, ranks)
    for name, rank in zip(("cf", "title"), ranks):
        if rank is not None and rank <= 10:
            stat[name] += 1
            stat[name + "_dcg"] += 1 / math.log2(rank + 1)
print("rows, in50, hits@10", row, stat["in50"], stat["cf"], stat["title"])
print("NDCG@10", round(stat["cf_dcg"] / row, 5), round(stat["title_dcg"] / row, 5))
'@ | python -B -
```

本实验每条只有一个正目标，第 r 名的贡献为 `1/log₂(1+r)`，前 10 以外为 0。手算一组极端情况：A 方案让 1 条请求命中第 1。B 方案让 2 条请求命中第 10。命中数从 1 到 2，但折扣后总分从 1 降到 `2/log₂(11)≈0.578`。这说明真实实验里的两个方向可以同时成立。若屏幕首屏很小，就进一步核对头部位置。要给“新排序提升点击”下结论，还需要有曝光和点击反馈的实验。

**迁移题。** 某版本的候选目标覆盖从 811/4,533 提升到 1,091/4,533，首页前十的命中却原地不动。你先调召回名额还是改排序？  
**答案。** 先逐行对照旧、新的候选集和前十结果，分出原本就覆盖、新救回、被挤出和两版都漏掉的请求。给相同候选分别使用两个排序器，再把同一排序器分别作用于两组候选。如果新增候选大多真实命中却总在第 11 以后，优先查分数尺度、跨路特征和排序训练样本。如果新召回既救回又挤掉大量原先靠前的好商品，名额分配本身也需要调整。对第 1 条那种两路都缺席的样本，改精排的边际收益是零。这一诊断也说明了生成式方案可能接手两个不同接口：只交付候选时仍需下游选择，直接生成有序推荐结果时还要对列表质量负责。[固定名额的两路召回对照](../traditional-lab/cold-title-results.json)
