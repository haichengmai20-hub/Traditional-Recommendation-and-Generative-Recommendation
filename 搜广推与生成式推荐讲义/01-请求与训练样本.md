# 第一篇　一次首页刷新，怎样成为下一条训练样本

[全书目录](README.md) · [下一篇](02-多路召回.md)

用户最近看过红色、白色的 PLA 线材，也看过透明 TPU 和蓝色 PETG。现在他打开首页。我们作为出题人知道，他下一次交互的商品是 3681，一卷橙色、直径 1.75 mm 的 ABS 线材。服务接到请求时只知道以前发生的事。**把时间轴遮在这一刻，是理解整本讲义的第一步。** 历史和目标取自 MiniOneRec Industrial 测试第 1 条；首页刷新、曝光、点击以及下文的时间线是用来说明生产系统的教学情境。[真实测试行](../mini-lab/evidence/test-first16.csv)

## 一套系统为什么要保留两张图

假设你负责商品库。你可以提前为 3,686 件商品分词、计算向量、统计“哪些用户同时和两件商品有过交互”。但你无法提前知道这个人此刻搜了什么、刚刚点了哪件商品，或商家刚好是否售罄。于是系统按信息何时可得，分成预计算与请求时计算两部分。[本项目目录规模](../traditional-lab/industrial-results.json) · [FunRec 在线与离线架构](https://datawhalechina.github.io/fun-rec/chapter_10_projects/2.architecture.html)

```text
商品表 + 历史事件 → 训练样本 → 模型、相似物品表、索引 → 带版本上线
                                                     ↓
用户刷新 → 取此刻可见的历史 → 候选 → 粗排 → 精排 → 组一页 → 客户端实际展示
                ↑                                      ↓
                └──── 下次请求可用的新行为 ← 点击、停留、成交
                                 └─ 按事件时间拼接，等待标签成熟 → 下次训练
```

线上每一层在回答不同的问题。召回回答“哪些商品值得看一眼”，交出一批商品 ID。粗排在时延预算内淘汰多数候选。精排给少量候选逐件打分，可以针对每件商品重新读取用户历史。重排看到一整个有序集合，能处理“前五件是不是同款”。商品服务最后还要取标题、价格和可售状态，客户端才能真的展示。**返回了、进了屏幕、被点击了**是三种事件。重排输出 20 件，用户只看了第一页的前 5 件，这次最多可以把 5 件记作被看到，要以客户端约定的曝光事件为准。[两阶段推荐架构](https://research.google/pubs/deep-neural-networks-for-youtube-recommendations/)

同一个目录也可以服务搜索和广告。用户明确搜“橙色 ABS 1.75 mm”时，多了一个请求级条件，要解释颜色和规格；商家购买广告位时，又多了谁有资格竞争、谁愿意出价、赢后怎么扣费。后面三个分支会沿用同一卷线材，方便观察**哪个输入改变了系统的决定**。

## 把四阶段接起来：视频 337 怎样到达屏幕

上面的商品数据记录了“下一次交互”。为了看清点击、观看和反向传播，再用旧稿 v3.1 的**视频封面列表**做一组教学推演。用户在请求 V17 看见封面，点击才开始播放。设目录有 100 万件物品、请求数 `B=1`、历史至多 `L=20` 条，向量宽度 `d=64`。本段的候选预算和观看日志都为教学设定。涉及 Amazon 线材的结果仍以本机数据为准。

先沿一件候选往前走。请求侧带进来的是原始 ID、时间和历史；学习到的向量在各自的模型内部查表。以下各层的预算均假定有足量合格候选。

| 步骤 | 吃进什么，直接算出什么 | 交给下一步什么 |
|---|---|---|
| 准备目录 | 召回版本 R1 的物品塔按批处理 `[N,88] → [N,64]`。每个视频的最终向量和真实 ID 一一关联 | 匹配 R1 的 ANN 索引 I1，以及可按 ID 查询的向量。视频 337 的目录记录还保存作者、类别、可用状态。 |
| 在线召回 | 用户、有效历史和上下文拼成 112 维，用户塔得到 `[1,64]`。拿这个向量查 I1 | 至多 1,000 个候选 ID 和相似度。假设 337 在其中，下游按 ID 读取它的属性与向量。[双塔内部怎么算](02-多路召回.md) |
| 粗排 | 粗排 P1 将两侧冻结的 64 维向量与自有的 16 维上下文拼成 144 维，输出每个候选的点击 logit | 按分数选出至多 200 个**位置**，用同一组位置取回原 ID 与随行字段。337 在新数组中的位置可能已变。 |
| 精排 | 精排 F1 用自己的表示对每个候选重读这 20 个历史位置，得到候选相关兴趣，再从 188 维输入分别预测点击和点击后长看 | 例如 337 的两项预测若为 0.50、0.80，其曝光后长看概率为 0.40，按教学效用 `0.4×0.50 + 0.6×0.40 = 0.44`。按效用截到 50 件。[精排计算与标签](03-粗排精排与重排.md) |
| 重排与曝光 | 重排逐个选入视频，每一步看它与已选视频的相似度、作者和类别，并检查资格。作者或类别过少时，允许返回短列表 | 系统返回至多 10 个 ID 与位置。假设客户端最终只确认 3 个有效曝光，337 是其中之一，用户点入并看了 35 秒。 |

顺着 337 查日志时要保留两样东西。一是请求的原始 `device_id/hour_id`，召回、粗排与精排分别用自己的表去编码。二是候选的真实 ID，后续按它查属性。若只重排分数而沿用原数组的行序取作者，就可能把 337 的分数配给另一个作者；第三篇用三个候选手算这次取数。

### 把没有字段名的维度落到数据

旧图给了 `content_features[16]` 和 `numeric_features[4]` 的宽度。下面补一套**可实现的教学定义**。时间截点用 V17 发起时刻；实际实现须读取当时已经到达并可用的快照。

| 字段 | 数据来源、变换与缺失处理 |
|---|---|
| 16 维内容特征（物品塔输入） | 对当时已发布的视频标题用固定版本文本编码器及投影得到 16 个数。标题变更时重算，记录编码版本，这一教学配置把它当作冻结输入。标题缺失用零向量，ID 和类别特征仍可用。 |
| 数值 1、2（精排输入） | 媒体元数据给出视频本身时长，发布记录给出距请求的小时数。对非负值取 `log1p`，缺失值用训练期该列变换后的中位数。视频本身时长在播放前就有，用户后来实际看的 35 秒只用于标签。 |
| 数值 3、4（精排输入） | 请求前 7 日的有效曝光数取 `log1p`；同窗口的平滑点击率取 `(成熟点击数 + α × 基准点击率)/(对应的成熟曝光数 + α)`，其中 `α>0`，基准点击率和 α 在训练期确定。无曝光的新品取 0 次曝光和基准点击率；统计服务缺报时用训练期约定的缺失值并另记故障。 |

### 再沿同一条曝光往回走

这次曝光的标签要等相应观察窗成熟。按本例“观看至少 10 秒算长看”，337 对应 `y_click=1, y_long=1`。构造各阶段输入时，都要回到 **V17 发起时** 的历史和特征；把点击前一秒新到的事件补给更早发起的 V17，也会穿越时间。

```text
V17 的请求快照 + 337 的有效曝光、点击、35秒观看
  ├─ 召回样本：请求前历史 → 正目标337 → 批内对比交叉熵 → 更新两塔及所属嵌入表，保存R1
  │                                                     ├─ 冻结物品塔，建I1并发布向量
  │                                                     └─ 用冻结两塔回算粗排训练向量
  ├─ 粗排样本：冻结的两侧向量 + 粗排上下文 → 点击BCE → 更新P1的上下文表及MLP
  └─ 精排样本：请求快照 + 候选337 → 点击BCE + λ×条件长看BCE → 更新F1自有表、DIN、共享层与任务头
上线：匹配的 R1、I1、P1、F1 和重排规则一起回放、灰度 → 下一轮曝光
```

同一请求中，若另一张封面已曝光、窗口结束仍未点击，它给粗排和精排点击头提供负例，条件长看损失跳过这一行。服务端返回而用户从未看到的封面，不进本例的曝光点击损失；召回训练中从别行取的批内竞争物品另有采样含义。这个区别会延续到生成式推荐：预测用户下一件交互的 SID 能用商品序列训练；要学“用户看到它后会不会长看”，还得拿到对应的曝光与观看反馈。

## 给一次请求记账

下面是一个教学日志片段。线上建议用稳定的 request_id 串起每一步，实际曝光另有 impression_id。保留召回路、模型/索引版本、排序位置，之后才能还原现场。

| 时刻 | 服务或用户做的事 | 此刻能把什么写入记录 |
|---|---|---|
| 10:00:00 | 首页收到请求 R17，向特征服务要最近行为 | 用户上下文、历史截止时间、特征快照版本。给候选 3681 算特征时可以读当时已发布的标题。 |
| 10:00:00 之后 | 召回路交回列表，几层打分后返回一页 | 保存各层的候选、来源及截断位置。对未被展示的商品，日志能回答它在哪一层出局。 |
| 10:00:02 | 客户端上报商品 A、B、C 进入视区 | 这三件各有一次曝光。首屏之外的 D 只有服务端返回记录。 |
| 10:00:08 | 用户点了 B，下午买下 B | 在约定的点击窗口结束后，可给 A、B、C 的点击任务打 0、1、0。转化任务还要按约定的归因与观察窗回填。 |

假设 B 在 09:59 的累计销量是 17，10:05 的销量是 18。即使你在第二天批量制表，也该为 R17 取 17。进一步说，09:58 的一条行为若到 10:01 才入库，请求时同样读不到。训练拼接既要约束事件何时发生，也要考虑数据何时到达线上。否则离线模型仿佛会预知未来，部署后同名特征却取不出同样的值。时间点拼接能帮助还原历史时刻的特征值，迟到事件仍需要按实际系统的可用时间处理。[Feast 的时间点拼接](https://docs.feast.dev/getting-started/concepts/point-in-time-joins)

## 从日志变出三种训练题

| 学习任务 | 模型输入 | 监督信号及分母 | 这份 Industrial CSV 能提供什么 |
|---|---|---|---|
| 下一件商品预测 | 截止当前的历史序列 | 每行一个真实下一商品，按全部测试行计命中率 | 有历史、目标商品及对应 SID，可直接做。未观察商品的负采样策略由训练者定义。 |
| 曝光后的点击预估 | 请求上下文和已曝光的候选 | 约定观察窗中的有效点击，分母是满足条件的实际曝光 | 缺逐次曝光、位置及显式未点击标签。要建这个任务得换到有曝光日志的数据。 |
| 搜索相关性 | 用户查询与候选商品 | 人工或业务定义的查询–商品匹配等级，可按查询评排序 | 缺查询及相关性判断。第四篇另给带判断的数据和能在本地运行的检索实验。 |

一次推荐实验很容易在这里换了题目。假设测试行只有一个目标，系统在 100 行中把它找回 20 次，HR@K 就是 20/100。如果系统为每行返回 5 件，500 件被返回的商品中有 20 件与真实下一件相等，按这个协议算 Precision@5 是 20/500。**这两个分数来自同一批输出；两者都没有用到线上点击。** 若要估点击率，还需要实际曝光与点击的分子、分母。

## 动手拆一行

在项目根目录运行下面的 PowerShell。第一个命令会显示模型能读到的历史和评分器保留的目标。第二个命令给出两个容易被忽略的测试切片。

```powershell
$first = Import-Csv -LiteralPath '.\mini-lab\evidence\test-first16.csv' | Select-Object -First 1
$first | Select-Object history_item_id, item_id, item_sid | Format-List
(Get-Content -Raw -Encoding utf8 '.\traditional-lab\industrial-results.json' | ConvertFrom-Json).diagnostics
```

你会看到 10 个历史 ID，最后一个是 3669，目标是 3681。全测试有 4,533 行，147 行的目标没在训练交互里出现，128 行的目标已在该行历史里出现过。前者能检查冷商品是否缺少共现边，后者提醒你核对去重策略。如果业务允许买家再次购买耗材，把历史商品全部剔除会让这 128 行注定无法命中。[测试诊断及计数](../traditional-lab/industrial-results.json)

## 先作答，再看解析

1. 工程师发现“某商品几乎没被点”，准备把它标成低质量。你先查哪两个数？ **参考答案**　先查符合资格的请求里它进入候选多少次，再查实际曝光多少次。若有大量请求压根没召回它，可以改召回或目录接入；若经常曝光、点击仍低，再按位置、场景及人群切分，检查相关性或展示质量。
2. 把测试第 1 条的目标题名也拼进用户历史，模型效果猛涨。怎样验证？ **参考答案**　打印推理输入并检查历史截止点。真实请求发生时只有前 10 条，目标标题是评分标签。移除目标后重测，对比前后差距才能定位信息泄漏。
3. 商品已在粗排前 50，最终客户端没看到它。只留最终展示日志能定位吗？ **参考答案**　还缺粗排与精排保留列表、重排过滤原因、客户端是否真正进入视区。沿同一 request_id 找第一次从“有”变“无”的边，比直接调最终模型更能区分原因。
