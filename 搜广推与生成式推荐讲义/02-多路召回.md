# 02 多路召回：从全库里找出值得继续算的商品

[全书目录](README.md) · [上一篇](01-请求与训练样本.md) · [下一篇](03-粗排精排与重排.md)

打开首页时，用户没输入搜索词。系统知道他刚看过几种 3D 打印线材，要从商品目录里给下一层交一份名单。这一层叫**召回**。它交出的是候选商品 ID，通常还附上来源、该路分数、该路名次。下游可以重新打分，却只能处理已经收到的商品。

我们用 MiniOneRec 的 Amazon Industrial 评论交互序列做实验。每条测试行给出一段历史和一个真实的下一商品，目录有 3,686 件商品，给召回的名额固定为 50。**单行判断是“目标商品 ID 进前 50 了吗”。全体指标 HR@50 是命中的测试行数除以 4,533。** 每行只设一个正目标，这里的逐行 Recall@50 与 HR@50 相同。真实曝光日志还可以问“是否点了返回列表”，本数据只能观察后续评论交互。[数据目录](https://github.com/AkaliKong/MiniOneRec/tree/main/data/Amazon) · [评测分母与文件哈希](../traditional-lab/industrial-results.json)

## 两条请求中的线索

| 测试行（从 1 起算） | 请求时能看到什么 | 事后揭晓的目标 | 把它当作哪道诊断题 |
|---|---|---|---|
| 1 | 10 件历史商品。最近三件依次是粉色 PLA、透明 TPU、蓝色 PETG，都是 1.75 mm 线材 | 橙色 1.75 mm ABS，ID 3681 | 需求大类很清楚，但这件商品在训练期有多少行为信号？ |
| 12 | 4 件历史商品，包括一卷透明自熔胶带（950），最后一件是切削液（40） | 同品牌黑色自熔胶带，ID 450 | 候选是因为全站热度、某次行为，还是几件历史商品共同入选的？ |

下面先让模型只看同一批用户曾经与什么商品交互，再给它看目录标题。两条请求和目标始终相同。[样本原表](../mini-lab/Amazon/test/Industrial_and_Scientific_5_2016-10-2018-11.csv)

## 第一版：热门商品，所有人共用一份榜单

`fit` 读取训练 CSV，把**同一用户所有训练行中的历史及目标**合并为一组商品。若训练行依次给出“看过 A，下一个 B”和“看过 A、B，下一个 C”，这个用户对 A 的计数只贡献 1 次。令 `n(i)` 为接触过商品 i 的训练用户数。MostPop（也叫 TopPop）按 `n(i)` 从高到低排，并列按商品编号从小到大排。离线就能算好榜单，在线取前 50 即可。这个版本没有使用当前用户看过什么。[本项目的 fit 与并列规则](../traditional-lab/itemcf.py)

第 12 条的黑色胶带有 43 位训练用户接触过，热门榜第 **108**，进不了前 50。第 1 条的橙色 ABS 有 **0** 位训练用户接触过，在本目录和并列规则下排第 **3,686**。同样是漏召，前者已有行为、缺个性化，后者还缺这件物品的行为信息。往这张榜单里加用户历史，可能先救回胶带。

## 第二版：从“大家常选什么”变成“见过它的人还选什么”

把训练集写成一个二值矩阵，行是用户，列是商品，同一用户接触过某商品就记 1。两列的点积 `n(i,j)` 正好等于两件商品共同的用户数。仅按共现次数排序会偏爱本来就很热的物品，因此这里用余弦归一化。请求到达后，把历史中不同商品投给候选的分数相加。

```text
sim(i,j) = n(i,j) / √(n(i) × n(j))       已共现的不同商品才建边
score(j | 历史) = Σ sim(i,j)             i 遍历去重后的历史商品
```

**手算第 12 条。** 透明胶带 950 有 50 位训练用户，黑色胶带 450 有 43 位，其中 7 位两种都用过。切削液 40 有 69 位，其中 2 位还用过黑色胶带。另两件历史商品与 450 的共现数都是 0。

```text
950 → 450      7 / √(50 × 43) = 0.150966
 40 → 450      2 / √(69 × 43) = 0.036717
总分                            0.187683
```

按这个分数给全目录排序，450 从热门榜第 108 到 ItemCF 第 **13**。分数表示邻居对候选的支持程度，数值无需落在 0 到 1 之间。脚本给有正分的商品排序后，按热门榜补齐零分候选。历史中的商品也可以再次入选，本数据有 128 条测试行确实重复了过去的商品。这里把历史当集合，若调换两条行为的先后，ItemCF 的输出相同。要表达“最近一次行为更重要”，可以引入时间衰减并另行评测。[实现中的 rank_itemcf](../traditional-lab/itemcf.py) · [ItemCF 方法与训练示例](https://datawhalechina.github.io/fun-rec/chapter_1_retrieval/1.cf/1.itemcf.html)

第 1 条的物品 3681 从未被训练用户接触过。实现只为共现数大于零的商品对建边，查询的 10 个历史商品都无法给 3681 投票，它仍然排第 3,686。服务端可离线缓存每件商品的前若干邻居，在线把用户最近的几张邻居表相加。不过邻居表截得越短，候选会越少。历史很长的用户在离线建两两共现时也会贡献许多商品对。**给冷商品换一个相似度分母，仍得不到第一条边。** 内容召回提供了另一种信号。[协同过滤的冷启动与内容召回实例](https://research.google/pubs/content-based-related-video-recommendations/)

## 第三版：给没有共现的物品一条凭标题入场的路

这次沿用前 40 个 ItemCF 候选，另留 10 个名额给标题。`index_titles` 先把全目录标题转小写、切词，保留数字里的小数点，`1.75` 可以成为一个词。商品标题 j 中词 t 的权重为 `出现次数 × [1 + ln((目录标题数 + 1)/(包含词 t 的标题数 + 1))]`。稀有词权重大。把整条标题向量除以自身长度，长标题不会仅凭词多获得更大的向量模长。

线上把最近 3 件历史商品的**单位标题向量相加**，得到当前兴趣向量。用倒排表从词找到含该词的标题，只在共同的词上累加点积。先排除 ItemCF 已经占下的 40 件，再从有词重合的商品里补 10 件，不足时回到 ItemCF 续补。它按两个通道分配名额，免去了把共现分和文本分直接相加时的量纲选择。[标题索引与去重代码](../traditional-lab/cold_title_recall.py)

**手算标题贡献。** 假设只考虑“线材”和“ABS”，最近两件归一化标题向量分别是 `(1,0)` 和 `(0.6,0.8)`。兴趣向量为 `(1.6,0.8)`。候选 A 是 `(1,0)`，得 1.6。候选 B 是 `(0.6,0.8)`，得 1.60。即使 B 有材料词，也可能与通用线材打平。实际历史出现了 PLA、TPU、PETG，目标却是 ABS。仅凭共享口径和类目，很难确定下一卷的材料。第 1 条在排除 CF 前 40 后，目标在有词匹配的标题结果中排第 **86**，只给标题 10 个名额仍会漏掉它。这个具体名次可以用本节末的命令复现。

## 用双塔学习相似性，用 ANN 减少查找时间

### 同一个视频 ID，什么时候查表，什么时候过塔？

上面的标题路按人为指定的词权重比较相似度。双塔则用历史正向交互学习“什么样的用户和什么样的物品应该靠近”。下面用**点击封面后播放视频的教学配置**走一遍。请求 V17 到来时，用户尚未看到视频 337。假设之后点击它并看了 35 秒，在本例“至少 10 秒”的正例定义下，这次请求可在离线训练时和 337 配成一对。本节的模型与百万级目录用于讲计算，前面的 Amazon 实测采用商品评论、ItemCF 与标题检索。[双塔训练与导出实例](https://www.tensorflow.org/recommenders/examples/basic_retrieval)

| 输入给谁 | 原始字段从哪里来 | 召回模型如何使用 |
|---|---|---|
| 用户塔 | 请求的 `user_id`、`device_id` 和请求时间派生的 `hour_id` | 分别查召回自己的三张可学习表，得到 32、8、8 维。 |
| 用户塔的历史分支 | 请求前的最近 20 个 `history_item_ids` 和有效位 mask | 每个 ID 查同一张召回物品表 `E_item_ret`，得 `[1,20,64]`。只对有效行取均值，得到 64 维兴趣。历史为空时取零，仍可用用户和上下文。 |
| 物品塔 | 目录快照的 `item_id`、`category_id`、标题 | ID 查 `E_item_ret` 得 64 维，类目查召回类目表得 8 维。标题用固定版本的文本编码与投影预先得到 16 维，缺标题填零。新 ID 可走预留的未知 ID 行，其区分信息主要来自类目与标题。 |

```text
请求 V17   [用户 32 | 历史均值 64 | 设备 8 | 小时 8] → 112 → MLP 128 → 64 → L2 归一化 → q
视频 337   [物品 ID 64 | 类目 8 | 标题内容 16]       →  88 → MLP 128 → 64 → L2 归一化 → v337
```

同一张 `E_item_ret` 的一行是 **ID 查表向量**。用户塔读取历史时直接用这些行，物品塔还会把该行与类目、内容拼接再变换。索引存的是后者得到的**物品塔输出**（或其压缩表示）。两者恰好都是 64 维，用错也可能顺利完成矩阵乘法，但点积已经换了含义。精排还可以有独立的 `E_item_rank`，用它对候选与历史做交互。在两塔间只做 `q·v`，就能预先计算所有物品向量；随候选而变的复杂兴趣计算可留给下游。

### 一个 batch 怎样同时训练两座塔？

取 `M=256` 对“请求时历史、后来发生正向交互的物品”，使第 a 个请求与第 a 个物品配对。两座塔分别产出 `U[M,64]` 和 `V[M,64]`。算 `S = U @ V.T / τ` 得 `[M,M]`；第 a 行是该请求对同批全部物品的 logits，第 a 列是它的目标位置。按行做交叉熵，代码可写成 `cross_entropy(S, arange(M))`，标签是**批内列号**。在线候选名额 K 与这里的 M 各自设置。[TFRS 对配对顺序、温度和批内负例的定义](https://www.tensorflow.org/recommenders/api_docs/python/tfrs/tasks/Retrieval)

手算其中一行。设三件物品与请求的归一化内积依次为 0.8、0.4、0，第一件是正例。温度 τ=0.4 时 logits 为 2、1、0，正例在三列之间的概率为 `e²/(e²+e+1)≈0.665`，该行损失约 0.408。减小正温度会放大差距，使这一行的 softmax 更尖；对一组固定向量单独乘相同的正系数，物品名次保持不变。这一分母描述批内竞争，点击概率另需曝光和点击标签。

非对角项充当对照，但两个请求可能都把 337 作为正例。此时同一物品又出现在另一列，需按 ID 屏蔽该意外负例，或把多个正列按多正例目标处理。换成不同 ID 仍可能是用户会喜欢的物品；热门物品被抽入分母的频率也更高。可估计采样概率做校正，再用同一整库测试 HR@K。反传时，一行 softmax 的梯度与“各列概率减去正例指示”成正比，同时流入用户塔、物品塔及参与计算的召回查表参数。`E_item_ret` 汇合历史和候选两条路径的梯度；本例预计算的标题编码冻结。[Google 双塔采样偏差研究](https://research.google/pubs/sampling-bias-corrected-neural-modeling-for-large-corpus-item-recommendations/)

### 塔输出向量，服务怎样把视频 ID 交给粗排？

1. 训练完保存两座塔和表参数为 R1。冻结 R1，对目录 N 个有效物品分批跑物品塔，产出 `[N,64]` 的向量、索引标签到业务 ID 的映射，构建索引 I1；另存 `item_id → R1 物品向量` 给下游取用。建索引发生在训练完成后，召回 loss 的梯度停留在模型及其可学习参数。
2. 在线只对请求算一次 `q[1,64]`。用它查 I1，取近邻标签与匹配分，再经映射得 `candidate_ids[1,1000]` 及逐位对齐的分数，附上召回来源和路内名次。第 7 个候选可能是业务 ID 337；7 是返回次序，337 才能用来查视频特征。若索引直接存业务 ID 作标签，这一步映射即为恒等。
3. 本教学配置让粗排 P1 复用冻结的 R1：按候选 ID 取对应物品塔输出，与用户塔输出、粗排自己的设备和小时嵌入拼成 `64+64+16=144` 维。若物品塔更新为 R2，需要重新编码受影响条目并刷新或重建索引，同时同步向量库。发布时验证在线用户塔、索引、向量库和 P1 的兼容性；同为 64 维也可能已换了表示空间。是否重训 P1 取决于其保留率和效果验证。[粗排如何消费候选与特征](03-粗排精排与重排.md)

**ANN 解决固定向量后的查找成本。** 小目录可对每个物品精确算内积。放大规模后可以先把物品向量聚成许多簇，每次只进几簇打分。以 IVF 为例，探查的簇数越少，通常查得越快，也越可能错过边界附近的好商品。换塔、换归一化方式、更新目录后要核对索引版本。若计算余弦，须让向量归一化与索引距离设置一致。[Faiss 的索引选择与参数](https://github.com/facebookresearch/faiss/wiki/Guidelines-to-choose-an-index) · [精确与近似检索对照](https://www.tensorflow.org/recommenders/examples/efficient_serving)

| 同一请求、同一组向量、相同 K | 如何归因 |
|---|---|
| 目标在精确 Top-50 内，ANN Top-50 漏掉，目录与索引版本一致 | 先扫更大的检索范围，画“ANN 对精确 Top-50 的重叠率—P95 延迟”曲线，同时看真实目标命中。 |
| 精确与 ANN 的 Top-50 都漏掉目标 | 在现有分数下增加 ANN 精度最多逼近精确结果。先查资格、表示、负采样或增加互补通道。 |
| 精确查询使用了新目录，ANN 查的是昨日目录 | 先统一商品快照再诊断。此时重叠率混合了索引新鲜度和近似搜索两种误差。 |

`ANN 重叠率@K = |近似 Top-K ∩ 精确 Top-K| / K` 的参照物是模型的精确排序。`HR@K` 的参照物则是真实下一商品。两者可能一个升一个不动。

读 TIGER 时，先画出候选 ID 的两条来路。传统双塔产生一个 q，在预计算的 v 上搜近邻得到候选 ID。TIGER 的解码器逐步产生目标 SID，再从目录映回候选物品。换了提出候选的计算方法，两边仍可接同一套商品资格检查和下游排序。[TIGER 与语义 ID](06-TIGER与语义ID.md)

## 动手：亲自把两条请求跑到候选边界

在与 `traditional-lab`、`mini-lab` 同级的项目根目录运行以下 PowerShell。只读数据，不写文件。

```powershell
@'
from itertools import islice
from pathlib import Path
import sys
sys.path.insert(0, "traditional-lab")
import itemcf as cf
import cold_title_recall as title

root = Path("mini-lab/Amazon")
info = root / "info" / (cf.DATASET + ".txt")
catalog = cf.read_catalog(info)
neighbors, popular, counts, _, _ = cf.fit(root / "train" / (cf.DATASET + ".csv"), catalog)
vectors, postings = title.index_titles(info)
test = cf.rows(root / "test" / (cf.DATASET + ".csv"), catalog)

for line, (_, history, target) in enumerate(islice(test, 12), 1):
    if line in (1, 12):
        ranked = list(cf.rank_itemcf(history, neighbors, popular, counts))
        extra = title.title_candidates(history, vectors, postings, set(ranked[:40]), len(catalog))
        title_rank = extra.index(target) + 1 if target in extra else None
        print(line, target, counts[target], popular.index(target) + 1, ranked.index(target) + 1, title_rank)
'@ | python -B -
```

输出列依次为测试行、目标、训练用户数、热门名次、ItemCF 名次和排除前 40 后的标题名次。预期两行是 `1 3681 0 3686 3686 86` 和 `12 450 43 108 13 None`。胶带的 `None` 是因为它已进 CF 前 40，标题路主动排除了它。如果要复核上表的整组计数，运行 `python -B traditional-lab/cold_title_recall.py mini-lab/Amazon`。

**迁移题。** 另一个商品的双塔精确内积把它排在第 9，线上 ANN 返回第 70。同一请求另有一款新商品根本不在索引快照里。两者各先查什么？  
**答案。** 前者先确认向量、度量和资格过滤一致，再加大 ANN 检索范围测试能否挽回。后者先查目录发布、向量生成与索引增量更新，给不存在的条目多分几次搜索也不会返回它。进入下一章时把条件换一下：胶带已进前 50，剩下的问题是如何选出要展示的前 10。[粗排、精排与重排](03-粗排精排与重排.md)
