# 搜广推与生成式推荐讲义

**同一卷橙色 ABS 打印线材，为什么首页找不到，搜一下就能排第二？** 在这套讲义的真实商品目录里，传统 ItemCF 没把它送进前 50。用户如果明确输入英文的颜色、材料和直径，标题检索就把它排到了第 2。把原来的行为历史送给生成式推荐模型，它猜中了目标商品编码的前两位，却把最后一位排在 21 个合法选项中的第 19。商品相同，三次请求能用的证据、系统搜索的空间和做错决定的位置都不同。[传统召回实测](../traditional-lab/industrial-results.json) · [搜索实验与原查询](04-搜索与查询相关性.md) · [生成模型逐码实测](../mini-lab/evidence/target-prefix-trace.json)

**推荐主线按 01 → 02 → 03 → 06 → 07 → 08 → 09 → 10 阅读。** 前三篇沿一次请求正向追踪候选，再沿一条反馈反向追踪参数更新。从第六篇起，对照传统方法、SASRec 的物品级序列预测和 TIGER 的逐码预测，再看 OneRec 怎样把生成扩展到排序与偏好学习。第九、十篇回到同一商品目录，用原始预测检查究竟该换哪一步。第四篇搜索和第五篇广告可在需要查询相关性、竞价或计费时单独查阅。

### 旧路线里最值得保留的两次推演

- **沿候选往前。** 在视频封面请求 V17 中，跟着视频 337，从物品塔向量、ANN 返回的 ID，一直走到粗排、精排和客户端曝光。每到一层，问清楚上一层交的是 ID、向量、概率，还是数组位置。旧稿的百万目录与 `1000 → 200 → 50 → 最多10` 用来演示接口；线上系统按时延和候选质量定预算。[第一篇的完整请求](01-请求与训练样本.md#把四阶段接起来视频-337-怎样到达屏幕)
- **沿反馈往回。** 把“337 被点击、观看 35 秒”放回同一份请求快照，分别构造召回正样本、粗排点击样本、精排双任务样本。找出哪个损失更新哪张表；换成生成式召回时，再检查原粗排还从哪里取向量。Amazon 的橙色线材与胶带继续承担真实下一商品预测的验证。[样本与参数更新](01-请求与训练样本.md#再沿同一条曝光往回走) · [生成式替换实验](10-怎样决定替换哪个组件.md)

**一道会改变改版决定的验收题。** 假设用户向量为 `(1,0)`，视频 337、501 的向量分别为 `(1,0)`、`(0,1)`。新版本把两个塔的所有输出同时乘以 −1。若只发新用户塔、仍查旧索引，内积分数从 `[1,0]` 变成 `[−1,0]`，501 会排在 337 前面。若索引也刷新，两边同步变号后内积恢复成 `[1,0]`。现在再看旧粗排：若它直接读物品向量的第一维当 logit，两件的分数仍会从 `[1,0]` 变为 `[−1,0]`，粗排次序翻转。这个手算例说明，验收改版需要同时回放**召回与下游排序**。若粗排只用内积，同样的变号对它没有影响；是否适配或重训，取决于它实际消费的特征。

## 怎样核对书里的结果

把项目根目录 `搜广推和生成式` 作为终端工作目录。正文里的“小例子”“假设”用于手算；写明“本机实测”的段落可以对照脚本、输入或输出文件；快手线上指标的出处是对应论文的实验表。Industrial 文件来自评论交互，能验证下一物品预测。搜索篇使用同目录和示例查询，广告篇使用明示假设的拍卖，二者各有适合实际业务评估的独立数据入口。

小红书帖子的项目追问已融入例题。例如“精排能不能救回漏召的商品”“排序指标增长后该检查哪些线上环节”。想核对帖子确实写了什么，可以回到每张原图的 OCR。论文效果与本地效果则分别回查作者对照实验和本机输出。[小红书导读](../03-小红书路线笔记导读.md) · [52 份逐图记录](../小红书核对记录/OCR/索引.md) · [MiniOneRec 实验环境与运行记录](../mini-lab/README.md)
